# 배송처 추가·제외 제안 (DSV 관리자 협의용)

상태: 제안. 구현하지 않음. DSV 관리자와 합의한 뒤 서버 계약과 앱을 개발한다.
요청 출처: DSV 배송원 SMS (2026-10-15).

## 1. 배송원이 겪는 상황

- 다음 날 배차를 확인하면 아래 경우가 생긴다.
  - 실제로 가야 하는 배송처가 리스트에 없다.
  - 리스트에 있지만 실물이 없거나, 물량이 많아 남겨 두고 가야 한다.
  - 다른 배송원과 배송처를 바꿔야 한다.
- 지금은 이런 일을 앱에서 처리할 메뉴가 없다.

## 2. 이미 있는 기능

| 상황 | 기존 기능 | 상태 |
| --- | --- | --- |
| 배송원끼리 바꾸기 | 주문 교환: 내 배송 → `전달` (상대가 수락하면 배정 변경) | 있음. 배송지 정보·지도 시트에서 바로 열리도록 개선함 |
| 내 배차에서 빼기 | 주문 교환: 내 배송 → `반납` (공용 배송으로) | 있음. 다른 배송원이 선착순으로 가져감 |
| 남이 반납한 배송 가져오기 | 주문 교환: 공용 배송 → `가져오기` | 있음 |
| 가서 배송하지 못함 | 미배송 보고 (사유 입력) | 있음. 배송 시작 후 사용 |

- 반납과 전달은 배송지 묶음 전체 단위다. 개별 주문만 빼는 기능은 없다.
- "배송 정보 → 주문 교환"과 "지도 시트 → 이 배송지 주문 교환"에서 해당 배송지가 맨 위에 강조되어 바로 전달·반납할 수 있다.

## 3. 새로 필요한 것과 선택지

### 3-1. 리스트에 없는 배송처 추가

| 안 | 흐름 | 장점 | 우려 |
| --- | --- | --- | --- |
| A. 추가 요청 (권장) | 배송원이 배송처명·주소·박스 수·사유를 보낸다. DSV 관리자 웹에서 승인하면 배차에 들어간다 | DSV 서버가 배정의 최종 권위를 유지한다. 주문·정산 근거가 남는다 | 승인 전에는 배송할 수 없다. 관리자 응답 시간이 필요하다 |
| B. 배송원 직접 추가 | 배송원이 바로 정류장을 추가한다. 관리자 웹에 "배송원 추가"로 표시된다 | 현장에서 즉시 처리된다 | 주문(SellerOrderKey) 없이 배송이 생긴다. 정산·고객 알림의 근거가 없다 |

### 3-2. 리스트의 배송처 제외 (실물 없음, 물량 초과)

| 안 | 흐름 | 비고 |
| --- | --- | --- |
| A. 기존 반납 사용 | 공용 배송으로 돌려 다른 배송원이 가져가게 한다 | 지금 바로 가능. "남겨 두고 간다"와 의미가 다를 수 있다 |
| B. 제외 요청 (권장) | 사유(실물 없음 / 물량 초과 / 기타)를 선택해 제외를 요청한다. 관리자가 승인하면 다음 배차로 넘기거나 취소한다 | 사유가 기록되고, 관리자가 재배차를 결정한다 |
| C. 미배송 보고 확장 | 배송 시작 전에도 미배송 보고를 허용한다 | 기존 보고 흐름을 재사용한다. 배송 전 제외와 섞인다 |

## 4. DSV 관리자에게 확인할 질문

1. 배송처 추가와 제외를 누가 최종 결정하는가? 배송원 즉시 처리인가, 관리자 승인인가?
2. 추가된 배송처에도 주문 번호(SellerOrderKey)와 고객사가 있어야 하는가? 정산은 어떻게 하는가?
3. 제외한 배송은 어떻게 처리하는가? 다음 날 재배차, 공용 배송, 취소 중 무엇인가?
4. 고객 알림(도착 예정 메일 등)은 추가·제외 시 어떻게 처리하는가?
5. 요청은 언제까지 받는가? 전날 배차 확인 시점만인가, 배송 당일에도 받는가?
6. 승인 응답이 늦을 때 배송원은 어떻게 해야 하는가?

## 5. 합의 후 개발 범위 (예상)

- 서버
  - 추가 요청과 제외 요청을 저장한다.
  - 관리자 승인과 거절 API를 만든다.
  - 승인되면 배차에 반영하고 경로를 재계산한다.
  - 감사 기록을 남긴다.
  - 숨김(심사) 데이터 분리 규칙을 따른다.
- 관리자 웹: 요청 목록과 승인·거절 화면.
- 앱
  - 배송 탭 메뉴에서 "배송처 추가 요청"을 연다.
  - 배송지 정보에서 "제외 요청"을 연다.
  - 요청 상태(대기, 승인, 거절)를 표시하고 알림을 받는다.
