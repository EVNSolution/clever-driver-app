## 1. 정차 후 출발 시 배송 자동 완료

### 사용자 요청

- 배정된 배송지에서 15분 이상 정차한 뒤 출발하면 해당 배송지를 자동 완료한다.
- 예정된 배송 순서와 관계없이 실제 방문한 배송지에 적용한다.
- 실제 방문에 맞게 배송 순서를 자동 변경한다.
- 환경설정에서 자동 완료를 켜고 끌 수 있다.

### 구현 인수 기준

- 같은 배송지의 나뉜 주문 전체를 한 묶음으로 처리한다.
- 15분이 되는 순간에는 완료하지 않고, 이후 출발이 확인됐을 때 처리한다.
- 짧은 정차, 단순 통과, GPS 오차·관측 공백을 15분 정차로 계산하지 않는다.
- 좌표가 없거나 여러 배송지를 구분할 수 없으면 자동 완료하지 않는다.
- 수동 완료, 이미 완료된 배송지, 요청 중복과 경합해도 중복 완료하지 않는다.
- 완료 실패를 성공으로 표시하지 않으며, 재시도로 중복 이벤트가 생기지 않는다.
- 설정 OFF, 로그아웃, 배차 변경 시 이전 배송지 정차 상태를 이어 쓰지 않는다.
- 완료된 배송지 묶음, 남은 배송 순서와 서버의 다음 배송지 표시가 일치한다.
- 사진 증빙을 자동 생성하거나 업로드한 것으로 표시하지 않는다.

### 확인 및 연결 필요

- 화면 잠금·다른 앱 사용 중에도 동작해야 하는지 사용자 확인 중.
- 정차·출발 거리와 위치 정확도 기준은 구현 시 명시하고 경계값을 검증한다.
- 앱의 현재 지도 위치 표시는 사용 중 권한만 사용하며 백그라운드 추적은 없다.
- 현재 순서 편집은 앱의 주문 배열을 바꾼다. 서버 순서 저장 계약은 미연결이다.
- 자동 완료와 증빙·마지막 배차 완료의 상호작용을 기존 완료 흐름과 함께 검증한다.

## 2. 환경설정의 문의사항

### 사용자 요청

- 환경설정에서 `문의사항` 화면으로 이동한다.
- 사용자는 제목과 내용만 입력한다.
- 작성자, 작성 날짜와 시각을 자동으로 기록하고 표시한다.
- 각 사용자는 자신의 문의 이력을 날짜·시간 순서로 조회한다.

### 구현 인수 기준

- 목록은 최신 작성순으로 표시한다. 같은 시각의 항목도 정렬이 안정적이어야 한다.
- 작성자는 인증된 계정으로 서버가 결정하고, 작성 시각도 서버가 기록한다.
- 다른 계정의 문의는 목록·상세 조회 모두 차단한다.
- 빈 제목·내용은 접수하지 않는다. 전송 중 중복 제출을 막는다.
- 접수 실패 시 입력을 보존하고, 서버 저장 성공 뒤에만 접수 완료를 표시한다.
- 앱 재실행·재로그인 후에도 본인의 접수 이력이 유지된다.
- 로딩, 문의 없음, 조회 실패와 제출 실패를 구분한다.

### 확인 및 연결 필요

- 현재 앱과 DSV 서버에 문의 생성·본인 목록·상세 조회 API가 없다.
- 서버 담당 작업에서 계정 인증, 저장, 작성자·시각 및 조회 권한 계약을 확정해야 한다.
- 로컬 메모를 접수된 문의로 표시하거나 예상 API를 호출하지 않는다.
- 서버 작업은 앱 워크트리의 수정 범위 밖이며, 확인된 서버 담당 채팅으로 넘긴다.
